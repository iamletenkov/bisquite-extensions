# pixelflux-v4l2m2m

Аппаратное кодирование H.264 в Selkies на платах, чей кодер выставлен
стандартным **V4L2 M2M**: Raspberry Pi 3/4 и CM4 (`bcm2835-codec`), а тем же
интерфейсом — RK356x и i.MX8M.

Расширение подменяет `pixelflux` внутри AppImage, который ставит `selkies`,
колесом апстрима с бэкендом `v4l2m2m`, и применяет правки совместимости
`lib/rc0-compat.py`.

## Состояние: ждёт апстрима

**Расширение пока не ставится и отказывается сознательно.** Бэкенд отправлен в
`selkies-project/pixelflux#35` и не влит, поэтому официального колеса с ним не
существует. В `install.sh` закрепление оставлено пустым, и он падает с внятным
отказом: образ, который молча получит софтовое кодирование, хуже несобранного.

После мерджа в закрепление вписываются тег коммита `main`, имя файла колеса и
`sha256` — предрелизы их CI публикует на каждый коммит.

## Что даёт

Замер на Raspberry Pi 4, живой рабочий стол 1080p, одна сессия, разница только
в `use_cpu`:

| | кадров | процессор |
|---|---|---|
| Железо (`v4l2m2m`) | 10.1 fps | **0.378 ядра** |
| Софт (x264) | 12.2 fps | **1.128 ядра** |

Втрое меньше процессора. Частота при этом у софта чуть выше: x264 раскладывается
на четыре ядра, а аппаратный движок кодирует по кадру за раз. Расширение продаёт
ядра, не частоту.

## Порядок в VMFILE

```
EXTENSION selkies ...
EXTENSION pixelflux-v4l2m2m
```

Строго после `selkies`: подменяется модуль внутри того AppImage, который тот
ставит. Поставленное раньше будет затёрто, и `install.sh` это проверяет.

## Что проверяется

**На сборке** — всё, что проверяемо без железа: `sha256` колеса, версия
модуля, что он импортируется и у `CaptureSettings` есть поле `codec`, что в
модуле присутствует сам бэкенд, что легли все девять правок совместимости.

**На первой загрузке** — служба `verify-pixelflux-v4l2m2m`: спрашивает у
pixelflux, объявлен ли `v4l2m2m` для h264, и **громко отказывает**, если нет.
Журнал сессии для этого не годится: строка `Encoder: …` появляется только при
подключённом клиенте, а у соседнего расширения такая строка однажды соврала.

## Чего расширение не делает

**Не ставится на платы без кодера.** На Pi 5 его нет в кремнии вовсе — там
расширение в цепочке указывать нельзя, и проверка первой загрузки это уронит.

**Не подкладывает libxcb и не собирает шим gbm.** Это болезни L4T, которые
лечит `pixelflux-tegra`; на Малине AppImage работает со своими библиотеками.

## Когда исчезнет

Когда выйдет релиз Selkies с парным pixelflux: мейнтейнер в `selkies#395`
сказал прямо, что наборы двигаются вместе и API между версиями несовместим.
Тогда `lib/rc0-compat.py` перестанет быть нужен, а расширение схлопнется до
установки колеса из релиза — либо исчезнет целиком, если бэкенд приедет в
самом AppImage.
