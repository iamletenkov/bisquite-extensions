# chromium

Ставит браузер Chromium — обычную сессию, не киоск (для киоска есть
`chromium-kiosk`).

## Манифест

| Поле | Значение |
|---|---|
| `phase` | `build`, `firstboot` |
| `arch` | `amd64`, `arm64` |
| `provides` | `browser` |
| `requires` | пусто |
| `conflicts` | пусто |

## Почему через snap, а не обычный `.deb`

С 19.10 у Canonical в архиве Ubuntu (в том числе jammy) `chromium-browser` —
**транзитный пакет**, не сам браузер:

```
$ apt-cache show chromium-browser
Installed-Size: 161
Description-en: Transitional package - chromium-browser -> chromium snap
```

Настоящий браузер ставит snap, который вызывает постинст этого пакета.
Нативного `.deb` для jammy у Canonical нет вовсе — это не решение
расширения, а факт архива.

## Два шага, а не один

`build` ставит транзитный пакет (это и запускает постинст, который
пытается поставить snap), `firstboot` — доводит дело, если сборка не
успела: постинст выполняется внутри `virt-customize`, где нет работающего
systemd и нет гарантии сети именно в момент установки пакета — тот же
класс проблемы, что уже встречался в проекте с постинстами, пытающимися
стартовать сервис под эмуляцией.

`configure.sh` на первой загрузке сначала проверяет, не появился ли
`chromium`/`chromium-browser` в PATH (тогда постинст уже справился —
быстрый выход без работы), и только если нет — ждёт `snap wait system
seed.loaded` и ставит `snap chromium` явно, с повторами (пакет тяжёлый,
сотни мегабайт, сеть могла не устояться).

## Проверено

Пакет `chromium-browser` подтверждён в apt на живой плате (Jetson, jammy,
arm64), 2026-09-12. Полный прогон (сборка образа + первая загрузка +
факт появления браузера) на момент написания не выполнялся — см. план
в основном репозитории.
