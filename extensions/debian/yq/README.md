# yq

Ставит `yq` — статический бинарь [mikefarah/yq](https://github.com/mikefarah/yq)
в `/usr/local/bin/yq`.

## Зачем отдельным расширением

**Имя `yq` носят два разных инструмента**, и языки запросов у них
несовместимы:

| | откуда | язык |
|---|---|---|
| kislyuk/yq | `apt install yq` в Debian/Ubuntu | jq |
| mikefarah/yq | бинарь с GitHub | свой |

Выражение `.x // empty` законно у первого и отвергается вторым —
`Error: invalid input text "empty"`.

Пока каждое расширение ставило `yq` само («пакет, если есть; бинарь,
если нет»), один и тот же VMFILE давал **разный инструмент на разных
дистрибутивах**. Хуже того, расхождение проявлялось не на сборке,
а на первой загрузке устройства: замер 2026-09-06 на Jetson Nano —
три службы настройки упали с «не дождался пользователя cloud-init»,
хотя пользователь существовал с первых секунд.

Одно расширение — один инструмент, всегда один и тот же.

## Параметры

| Переменная | Умолчание | Что делает |
|---|---|---|
| `YQ_VERSION` | `v4.45.1` | версия релиза mikefarah/yq |

Версия прибита намеренно: `latest` означал бы, что тот же VMFILE
завтра соберёт другой образ.

## Куда ставить в VMFILE

**До** расширений, которые читают конфигурацию: `code-server`,
`kiosk`, `chromium-kiosk`, а также любых, чей `configure.sh` на первой
загрузке зовёт `get_cloud_user.sh`.

```
EXTENSION yq
EXTENSION code-server CODE_SERVER_BIND=127.0.0.1
```

## Чего оно не делает

Не удаляет уже установленный `yq` из пакета: если он найден,
расширение кладёт свой в `/usr/local/bin`, который в PATH идёт раньше
`/usr/bin`, и говорит об этом предупреждением. Удалять пакет —
значит трогать зависимости, которых расширение не ставило.
